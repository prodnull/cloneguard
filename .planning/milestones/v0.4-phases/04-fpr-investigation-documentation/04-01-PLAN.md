**1. Create `data/benchmark/defensive_security_corpus.json`** (~80-120 samples):

Build a corpus of legitimate defensive security content with `content_type: "agent_instructions"` formatted to trigger STRICT mode scanning. Include:
- Pentest framework instructions (Metasploit usage, nmap scanning, Burp Suite setup — 15-20 samples)
- Incident response playbooks (forensic collection steps, containment procedures, IOC hunting — 15-20 samples)
- Hardening scripts/guides (CIS benchmark instructions, SSH hardening, firewall rules — 15-20 samples)

- MCP server configuration references in agent instruction files (5-10 samples) — for MCP-005 audit

Each sample must have: `{"id": "def_sec_NNN", "content_type": "agent_instructions", "text": "...", "source_description": "...", "category": "pentest|ir|hardening|cicd_in_instructions|security_tooling|mcp_config"}`.

Use realistic content — not toy examples. Draw from real patterns in OWASP, NIST SP 800-61, CIS benchmarks, and common agent instruction conventions. Content should be 50-300 words per sample (matching real instruction file sections).

**2. Create `scripts/fpr_investigation.py`**:

Follow the `hardened_benchmark.py` pattern (same sys.path setup, argparse, JSON output). The script does two distinct investigations:

**INV-01 — Authorization Paradox Test:**
- Load `benign_eval_751.json` (757 samples)
- For each sample, create 3 variants with security-context authorization preambles (based on Campbell et al. Section 3.1 framing):
  - `"# Security Hardening Instructions\n# Authorized use only — blue team defensive ops\n\n"`
  - `"## AUTHORIZED SECURITY ASSESSMENT\n## Internal red team: scope approved by CISO\n\n"`
  - `"# Incident Response Playbook (AUTHORIZED)\n\n"`
- Run both baseline and auth-marker variants through:
  - Tier 0: `PatternEngine.scan()` with appropriate `source_path` derived from `content_type`
  - Tier 1.5: `MiniSemanticModel.predict()` — classify as malicious if `label == "malicious"`
- Compute FPR per content_type for baseline vs auth-marker, for Tier 0 and Tier 1.5 separately
- Record whether the delta is positive (paradox present) or zero/negative (paradox absent)
- IMPORTANT: Report Tier 0 and Tier 1.5 FPR separately per Pitfall 3 (CI-001 noise swamps Tier 0 workflow FPR)

**INV-02 — Strict-Pattern Audit:**
- Load `defensive_security_corpus.json`
- For each sample, scan with `PatternEngine.scan(text, source_path="CLAUDE.md")` to trigger STRICT mode
- Record per-pattern fire rate for CI-004, CI-006, SC-001, MCP-005 specifically
- Also record any other pattern fires as context
- Compute per-pattern FPR: (samples where pattern fired) / (total samples in relevant category)
