**defaults/main.yml** -- Default variables (all overridable). Start the file with the YAML document separator then the variables. Key variables:
- `cloneguard_version: "latest"` -- Pin to specific version in production
- `cloneguard_install_method: "uv"` -- "uv", "pipx", or "pip"
- `cloneguard_extras: ["mini"]` -- Optional extras: mini, opa, cedar, splunk, sentinel, chronicle, governance
- `cloneguard_user: "{{ ansible_user_id }}"` -- note: Jinja2 template variable, literal in the YAML file
- `cloneguard_dry_run: true` -- MUST be true for initial rollout (safe default)
- `cloneguard_suspicious_floor: 0.3`
- `cloneguard_malicious_floor: 0.7`
- `cloneguard_sandbox_preferred: "auto"`
- `cloneguard_sandbox_fallback: "noop"`
- `cloneguard_policy_source: ""` -- Path to custom policy.yaml (overrides template)
- `cloneguard_hook_scope: "global"` -- "global" or "project"
- `cloneguard_hook_events: [InstructionsLoaded, PreToolUse, PostToolUse]`
- `cloneguard_policy_backend: "yaml"` -- "yaml", "opa", or "cedar"

**tasks/main.yml** -- Idempotent task list. Start with YAML document separator. Include these Ansible tasks using FQCN (ansible.builtin.*):

1. `Check if CloneGuard is already installed` -- ansible.builtin.command running `cloneguard --version`, register result, changed_when=false, failed_when=false
2. `Install CloneGuard via uv` -- ansible.builtin.command running `uv tool install cloneguard=={version}` with extras, when install_method=="uv" and not already installed at correct version, become=false
3. `Install CloneGuard via pipx` -- ansible.builtin.command running `pipx install cloneguard=={version}`, when install_method=="pipx" and not installed, become=false
4. `Install CloneGuard via pip` -- ansible.builtin.pip with name and state=present, when install_method=="pip"
5. `Ensure ~/.cloneguard directory exists` -- ansible.builtin.file, state=directory, mode="0700", become=false
6. `Deploy custom policy file` -- ansible.builtin.copy from cloneguard_policy_source, dest=~/.cloneguard/policy.yaml, mode="0600", backup=true, when policy_source is not empty, notify handler, become=false
7. `Deploy policy from template` -- ansible.builtin.template, src=policy.yaml.j2, dest=~/.cloneguard/policy.yaml, mode="0600", backup=true, when policy_source is empty, notify handler, become=false
8. `Ensure ~/.claude directory exists` -- ansible.builtin.file, state=directory, mode="0755", when hook_scope=="global", become=false
9. `Deploy hook settings (global)` -- ansible.builtin.template, src=settings.json.j2, dest=~/.claude/settings.json, mode="0644", backup=true, when hook_scope=="global", become=false

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Ansible controller to Target machines | Ansible pushes config over SSH; target machines trust the controller |
| MDM server to macOS devices | MDM pushes signed profiles; devices trust the MDM enrollment |
| Fleet templates to User config | Templates generate policy.yaml that the policy engine loads |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-13 | Tampering | fleet/ansible/tasks/main.yml | mitigate | Ansible playbook uses `backup: true` on file deployments. Policy files deployed with mode 0600 (user-only read/write). Playbook uses `become: false` for policy writing (user-owned files, not root). |
| T-05-14 | Elevation of Privilege | fleet/ansible/tasks/main.yml | mitigate | Playbook uses `become: false` for ALL tasks except package installation (which may need system pip). Policy files are owned by the target user, never root. No sudo for hook config. |
| T-05-15 | Tampering | fleet/mdm/*.mobileconfig | mitigate | Profiles shipped unsigned as templates. README documents signing requirement. MDM platforms (Jamf, Intune) verify profile signatures before deployment. Unsigned profiles trigger visible warnings on target devices. |
| T-05-16 | Spoofing | fleet/ansible/site.yml | accept | Ansible uses SSH key authentication. If attacker compromises Ansible controller, they have full access anyway. Standard Ansible security model applies. |
| T-05-17 | Information Disclosure | fleet/ansible/templates/policy.yaml.j2 | mitigate | Policy template contains thresholds and enforcement config, not secrets. No credentials in templates. SIEM tokens and SPIFFE config are separate from policy deployment. |
</threat_model>
