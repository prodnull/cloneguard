    """MCP tool description fingerprinting registry (D-17).

    Known-good registry of MCP tool descriptions with SHA-256 hash-based
    fingerprinting. Flags descriptions that deviate from registered versions
    as potential RADE attacks (tool description poisoning).

    Registry ships as JSON build artifact in detection/mcp_registry.json.
    Not loaded from network -- local package resource only.
    """

    Implement:
    1. `MCPRegistry` class:
       - `__init__(self, registry_path: Path | None = None)`: Load from provided path or default to `mcp_registry.json` in same directory
       - `_tools: dict[str, dict]` loaded from JSON
       - `_version: str`
       - Class method `load(cls, path: Path | None = None) -> MCPRegistry`

    2. `check_tool_fingerprint(self, tool_name: str, description: str, input_schema: str = "") -> bool | None`:
       - Return None if tool_name not in registry (unknown tool)
       - Compute `hashlib.sha256(description.encode()).hexdigest()`
       - If registry entry has non-empty description_hash: compare hashes. Return True if match, False if mismatch.
       - If registry entry has empty description_hash: fall back to description_length_range check. Return False if description length outside range.
       - Optionally check input_schema_hash if provided.

    3. `get_registered_tools(self) -> list[str]`: Return list of registered tool names.

    Module conventions: `from __future__ import annotations`, `import hashlib`, `import json`, `logging.getLogger(__name__)`, graceful degradation if JSON file missing.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| rules/ files -> PatternEngine | YAML rule files loaded at startup define detection patterns |
| MCP tool descriptions -> mcp_registry | Untrusted MCP tool descriptions compared against registry |
| mcp_registry.json -> MCPRegistry | Registry JSON defines known-good fingerprints |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-10 | Tampering | Pattern library injection | mitigate | Rules loaded from package directory (Path(__file__).parent / "rules"), not CWD. Attacker cannot inject rules via repo content. Existing PatternEngine security model preserved. |
| T-04-11 | Tampering | MCP registry poisoning | mitigate | Registry ships as JSON build artifact within the package. Not loaded from network or repo. Operator cannot modify without rebuilding package. Version-keyed entries enable stale detection. |
| T-04-12 | Spoofing | RADE attack evasion | accept | Fingerprinting is hash-based; attacker could craft description with same hash (SHA-256 collision -- computationally infeasible). Length-range fallback is weaker but catches gross modifications. Honest limitations documented in D-22 eval. |
| T-04-13 | Denial of Service | Recursive glob explosion | mitigate | glob("**/*.yaml") on package-internal directory with known structure. Max depth 2 (rules/category/file.yaml). No user-controlled directory traversal. Bounded at build time. |
</threat_model>
