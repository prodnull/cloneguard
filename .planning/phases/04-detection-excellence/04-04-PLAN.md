<objective>
Build the adversarial evaluation harness that measures the fusion pipeline's detection performance against existing corpora and new fusion-targeting payloads, following the "Attacker Moves Second" methodology.

Purpose: Phase 4 introduces significant detection changes (fusion, MELON, new patterns). Without rigorous adversarial evaluation, we cannot claim these changes improve detection or control FPR. The evaluation produces an honest report -- if fusion doesn't help in certain attack classes, that is reported transparently, consistent with the existing 16.7% bypass rate disclosure.

Output: Evaluation harness script, fusion-targeting test payloads, structured markdown report with per-attack-class results, FPR regression analysis, comparison to pre-fusion baseline, human verification of results.
</objective>

    Structure the script with these sections:

    1. **CLI arguments** (argparse):
       - `--corpus-dir` (default: `data/benchmark/`)
       - `--output` (default: `adversarial_eval_report.md`)
       - `--include-garak` (flag: include garak 13,597-probe baseline if data available)
       - `--include-ipi-arena` (flag: include IPI Arena dataset if data available)
       - `--fusion-only` (flag: evaluate fusion pipeline only, skip pre-fusion baseline comparison)
       - `--verbose` (flag: per-sample results)

    2. **Content type classifier** function:
       `classify_content_type(filename: str, content: str) -> str`
       Returns one of: "ci_config", "security_doc", "test_fixture", "mcp_tool_desc", "source_code", "other"
       - ci_config: filenames matching `*.yml`, `*.yaml` with workflow/pipeline markers, `Jenkinsfile`, `.github/workflows/*`
       - security_doc: filenames containing "security", "SECURITY", "threat", "vulnerability", content with CVSS/CVE references
       - test_fixture: filenames in `tests/`, `test_`, `fixtures/`, `__tests__/`
       - mcp_tool_desc: content with `"tools":`, `"description":` JSON-like MCP structures
       - source_code: `.py`, `.js`, `.ts`, `.go`, `.rs`, `.java` extensions
       - other: everything else

    3. **Fusion-targeting payloads** -- hardcoded test cases designed to stress the fusion layer:
       - Payloads that evade pattern detection but trigger semantic (e.g., bureaucratic-documentation format with hidden instructions -- the known 16.7% bypass vector)
       - Payloads that evade semantic but trigger pattern (e.g., base64-encoded exfiltration commands that patterns catch via encoding_obfuscation rules)
       - Payloads that evade both pattern and semantic but trigger sequence (e.g., benign-looking individual tool calls that form an exfiltration sequence)
       - Payloads that are ambiguous (should fall in 0.4-0.6 MELON zone)
       - At least 20 fusion-targeting payloads total across these categories

    4. **Evaluation pipeline**:
       ```python
       def evaluate(
           engine: DetectionEngine,
           samples: list[dict],  # {"content": str, "label": str, "source": str, "content_type": str}
       ) -> EvalResults:
       ```
       - For each sample: create ToolCallEvent, call engine.scan(), record verdict, confidence, signals, melon_triggered
       - Compute per-attack-class metrics: TPR (true positive rate), FPR (false positive rate), bypass rate
       - Compute per-content-type FPR
       - Track MELON trigger rate and MELON verdict upgrade rate

    5. **Report generation** function:
       `generate_report(results: EvalResults, output_path: str) -> None`
       Produces markdown report with:
       - **Summary**: Total samples, overall TPR, overall FPR, MELON trigger rate
       - **Per-attack-class results**: Table with attack_class | samples | detected | bypassed | bypass_rate
       - **Pre-fusion baseline comparison**: If baseline data available, show detection delta ("what fusion buys")
       - **Per-content-type FPR**: Table with content_type | benign_samples | false_positives | fpr
         Flag any content type exceeding 9.2% FPR baseline (D-08)
       - **MELON analysis**: Trigger count, upgrade count, circuit breaker trips, latency impact
       - **Fusion signal analysis**: For bypassed samples, show which signals fired and which didn't
       - **Honest disclosure**: "X out of Y samples bypassed all three signals. These represent [attack class] payloads. Fusion [did/did not] improve detection for this class compared to standalone Tier 0+1.5 baseline."

    6. **main()**: Load corpora, classify content types, run evaluation, generate report.

    Module conventions: `from __future__ import annotations`, argparse, `if __name__ == "__main__":` guard, no new dependencies.
