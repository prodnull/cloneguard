**1. Create `src/cloneguard/mahalanobis.py`:**

Implement `MahalanobisDetector` class per the research pattern:
- `fit(embeddings: np.ndarray, labels: np.ndarray)`: Compute per-class means and inverse covariances. Use `scipy.linalg.pinv` for numerical stability. Add diagonal shrinkage (default 1e-4, increase to 1e-3 if malicious class covariance is near-singular).
- `score(embedding: np.ndarray) -> float`: Minimum Mahalanobis distance across all class centers. Lower = typical, higher = anomalous.
- `is_anomalous(embedding: np.ndarray) -> bool`: `score(embedding) > self.threshold`.
- `fit_threshold(benign_embeddings: np.ndarray, target_fpr: float = 0.05) -> float`: Set threshold at (1-FPR) quantile of benign scores. Report Wilson 95% CI for actual FPR.
- `save(path)` / `load(path)`: Serialize to/from `.npz` (class_means, class_inv_covs, class_labels, threshold).

Use `scipy.linalg.pinv` (not `numpy.linalg.inv`). Consider LedoitWolf from scikit-learn if malicious class has < 1000 effective samples (3033 total, but augmented rounds may cluster tightly).

**2. Create `scripts/fit_mahalanobis.py`:**

Script to fit the Mahalanobis detector on training CLS embeddings:

- Print: per-class sample counts, threshold, actual FPR, Wilson CI

**1. Extend `MiniClassification` dataclass** in `mini_semantic.py`:

Add two new fields with defaults (backward-compatible):
```python
@dataclass
class MiniClassification:
    verdict: str
    confidence: float
    reason: str
    anomaly_score: float = 0.0      # NEW: Mahalanobis distance (0.0 = normal)
    anomaly_flagged: bool = False    # NEW: True when score exceeds threshold
```

**2. Modify `MiniSemanticClassifier.__init__()` and `_try_load()`:**

- After loading the ONNX session, check if `mahalanobis_params.npz` exists alongside the model
- If it exists, load `MahalanobisDetector` from it
- Store as `self._mahalanobis: MahalanobisDetector | None`
- If `.npz` not found, `self._mahalanobis = None` (graceful degradation — v3 models work without it)

**3. Modify `classify()` method:**

Current flow: `session.run(None, inputs)[0]` -> logits -> verdict.

New flow with v4 dual-output ONNX:
```python
outputs = self._session.run(None, {...})
logits = outputs[0][0]  # shape (2,)

# Extract CLS embedding if available (v4 dual-output)
cls_embedding = outputs[1][0] if len(outputs) > 1 else None

# Existing verdict logic unchanged...
result = MiniClassification(verdict=verdict, confidence=confidence, reason=reason)

# Mahalanobis scoring (if detector loaded and CLS available)
if self._mahalanobis is not None and cls_embedding is not None:
    anomaly_score = self._mahalanobis.score(cls_embedding)
    anomaly_flagged = self._mahalanobis.is_anomalous(cls_embedding)
    result.anomaly_score = anomaly_score
    result.anomaly_flagged = anomaly_flagged

    # Defense-in-depth escalation (per CONTEXT.md locked decision):
    # SAFE + Mahalanobis anomalous -> SUSPICIOUS
    if result.verdict == "SAFE" and anomaly_flagged:
        result.verdict = "SUSPICIOUS"
        result.reason = f"{result.reason} [Mahalanobis anomaly: score={anomaly_score:.2f}]"
```

**4. Apply the same pattern to `_classify_sliding_window()`:**

The sliding window returns `MiniClassification` objects per chunk. Each chunk's CLS embedding should be scored. The worst anomaly_score across chunks propagates to the final result.

**5. Backward compatibility:**

- `len(outputs) > 1` check ensures v3 ONNX models (single output) still work
- `self._mahalanobis is None` check ensures missing `.npz` doesn't break
- `anomaly_score` defaults to 0.0, `anomaly_flagged` defaults to False
- Existing consumers that don't read these fields see no behavior change
- Hook exit codes unchanged: SUSPICIOUS exits 0 (warning, not block) per CONTEXT.md

**6. Update `scanner.py` if needed:**

The `_run_tier2` method calls `mini.classify_files()` which returns `SemanticResult`. Check if `SemanticResult` / `SemanticFinding` needs `anomaly_score` fields. If the anomaly score only surfaces through `MiniClassification.verdict` (SAFE -> SUSPICIOUS escalation), no scanner changes are needed — the escalation is already in the classify() output. Add `anomaly_score` to `SemanticFinding` if downstream consumers need the raw score.

**IMPORTANT:** Run `uv run pytest tests/ -x -q` after changes to verify the existing 978-test suite still passes. The new fields have defaults, so existing tests should not break.
