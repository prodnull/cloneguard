    ```yaml
    name: 'CloneGuard Scan'
    description: 'Scan repository for prompt injection patterns and upload SARIF results'
    inputs:
      threshold:
        description: 'Override suspicious/malicious thresholds (e.g., "0.3/0.7")'
        required: false
        default: ''
      scan-paths:
        description: 'Directories to scan (comma-separated, defaults to repo root)'
        required: false
        default: '.'
      fail-on:
        description: 'Verdict level that fails the check (malicious or suspicious)'
        required: false
        default: 'malicious'
      python-version:
        description: 'Python version for uv'
        required: false
        default: '3.12'
    runs:
      using: composite
      steps:
        - name: Install uv
          uses: astral-sh/setup-uv@v5
        - name: Install CloneGuard
          shell: bash
          run: uv tool install cloneguard[mini]
        - name: Run scan
          id: scan
          shell: bash
          run: |
            EXIT_CODE=0
            cloneguard scan ${{ inputs.scan-paths }} \
              --sarif --output cloneguard-results.sarif \
              ${{ inputs.threshold && format('--threshold {0}', inputs.threshold) || '' }} || EXIT_CODE=$?
            echo "exit_code=$EXIT_CODE" >> "$GITHUB_OUTPUT"
            if [ "${{ inputs.fail-on }}" = "suspicious" ] && [ "$EXIT_CODE" -ge 1 ]; then
              exit 1
            elif [ "${{ inputs.fail-on }}" = "malicious" ] && [ "$EXIT_CODE" -ge 2 ]; then
              exit 1
            fi
        - name: Upload SARIF
          uses: github/codeql-action/upload-sarif@v4
          if: always()
          with:
            sarif_file: cloneguard-results.sarif
            category: cloneguard
    ```

    ```python
    """OTel span emitter for CloneGuard audit events (D-18).

    Emits OpenTelemetry spans conforming to GenAI semantic conventions (experimental).
    When opentelemetry-api is not installed, all methods are no-ops -- zero import
    overhead. When installed without an SDK, spans are NonRecordingSpan (zero export
    overhead). Export is configured via standard OTEL_EXPORTER_* environment variables
    (D-19) -- CloneGuard does not manage the collector.

    Threat model:
        T-03-12: Never include raw tool_input or gen_ai.tool.call.arguments in spans.
                  Only hashes, verdicts, and metadata. Span attributes are selected
                  explicitly from AuditEvent fields.
    """
    from __future__ import annotations

    import logging
    from typing import TYPE_CHECKING, Any

    if TYPE_CHECKING:
        from cloneguard.audit.types import AuditEvent

    logger = logging.getLogger(__name__)

    try:
        from opentelemetry import trace
        _tracer = trace.get_tracer(
            "cloneguard",
            schema_url="https://opentelemetry.io/schemas/1.29.0",
        )
        _OTEL_AVAILABLE = True
    except ImportError:
        _tracer = None
        _OTEL_AVAILABLE = False
    ```

    Class `OTelEmitter`:
    - Constructor: no arguments, no side effects. Store reference to module-level `_tracer`.
    - Property `available` -> `bool`: returns `_OTEL_AVAILABLE`
    - Method `emit(self, event: AuditEvent) -> None`:
      - If not `_OTEL_AVAILABLE` or `_tracer is None`: return immediately (no-op)
      - Create span via context manager:
        ```python
        with _tracer.start_as_current_span(
            name=f"cloneguard.scan {event.tool_name}",
            attributes={
                "gen_ai.system": event.agent_type,
                "gen_ai.operation.name": "execute_tool",
                "gen_ai.tool.name": event.tool_name,
                "cloneguard.verdict": event.verdict,
                "cloneguard.confidence": event.confidence,
                "cloneguard.enforcement_action": event.enforcement_action,
                "cloneguard.sandbox_adapter": event.sandbox_adapter,
                "cloneguard.source_path": event.source_path,
                "cloneguard.schema_version": event.schema_version,
            },
        ):
            pass  # Span auto-ends when context manager exits
        ```
      - NEVER include `event.tool_input_hash` in attributes (the hash itself is safe, but keeping attribute set minimal reduces exposure surface)
      - NEVER call `_tracer.get_tracer_provider().force_flush()` or any synchronous export (Pitfall 3 from research)
    - Wrap the entire emit() body in try/except to prevent OTel failures from breaking hook responses.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CloneGuard audit pipeline -> OTel collector | Span attributes cross from CloneGuard into external observability infrastructure. Must not leak sensitive content. |
| GitHub Actions runner -> SARIF upload | SARIF results uploaded to GitHub Security tab. Must not contain raw file content (only pattern matches). |
| GitHub webhook -> CICDAdapter | Webhook payloads from GitHub are not directly user-controlled but carry PR content which may contain injections. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-12 | Information Disclosure | OTelEmitter span attributes | mitigate | Span attributes are explicitly selected from AuditEvent fields. NEVER include gen_ai.tool.call.arguments, raw tool_input content, or file content. Only verdicts, confidence scores, tool names, and metadata. |
| T-03-13 | Information Disclosure | SARIF upload | accept | Existing SARIFEmitter uses matched_text (pattern name) not full file content. CI/CD action uploads this SARIF as-is. Risk is low -- SARIF is designed for security findings, not source code. SARIF goes to same-repo Security tab (same access boundary). |
| T-03-14 | Denial of Service | OTel span export blocking | mitigate | OTelEmitter never calls force_flush(). Span creation is synchronous (<1ms) but export is async via SDK BatchSpanProcessor. Documentation notes BatchSpanProcessor requirement. |
| T-03-15 | Tampering | GitHub Actions action.yml | accept | action.yml is in the CloneGuard repo and versioned via git tags. Users pin to @v1. Supply chain risk is standard for GitHub Actions -- mitigated by tag signing (future). |
| T-03-16 | Spoofing | CICDAdapter webhook payloads | mitigate | CICDAdapter normalizes webhook content and passes through DetectionEngine for scanning. Malicious PR content is the TARGET of scanning, not a bypass vector. Malformed webhooks produce empty ToolCallEvent (fail safe). |
</threat_model>
