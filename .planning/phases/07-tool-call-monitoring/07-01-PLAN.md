  <behavior>
    - ToolEvent dataclass holds session_id, tool_use_id, tool_name, tool_input, hook_event_name, ts
    - SequenceAlert dataclass holds rule_id, description, session_id, trigger_event, context_window
    - get_monitor() returns module-level singleton ToolCallMonitor
    - record_event(data) appends ToolEvent to per-session deque (maxlen=50), runs rules, logs alerts
    - record_event never raises (wrapped in try/except)
    - record_event never writes to stdout
    - Per-session deque capped at maxlen=50; session map capped at _MAX_SESSIONS=200 with LRU eviction
    - SEQ-001: Read(sensitive file) then WebFetch(external URL) within 10 events fires alert
    - SEQ-001: Read(non-sensitive file) then WebFetch does NOT fire
    - SEQ-001: Read(sensitive) then WebFetch(localhost) does NOT fire
    - SEQ-002: Read(sensitive file) then Bash(curl/wget to external URL) within 10 events fires alert
    - SEQ-002: Read(sensitive) then Bash(ls) does NOT fire
    - SEQ-003: Same mcp__* tool called >5 times within 10 events fires alert
    - SEQ-003: 5 calls (exactly threshold) does NOT fire
    - SEQ-004: Write(sensitive target like package.json/.github/) then Bash(npm/pip/make/build) fires alert
    - SEQ-004: Write(README.md) then Bash(build) does NOT fire
    - _is_sensitive_file returns True for .env, .ssh/*, id_rsa, credentials, secrets, tokens, passwords
    - _extract_external_url returns URL for WebFetch with external host, None for localhost/safe hosts
    - _extract_external_url returns URL from Bash commands containing curl/wget https://...
    - Log entry is valid JSON with ts, rule_id, description, session_id, trigger, context_window
    - record_event completes in under 5ms per call (latency test)
  </behavior>

    **Write implementation (GREEN):**
    Create `src/cloneguard/monitor.py` following RESEARCH.md Pattern 1-4:

    1. Dataclasses: `ToolEvent` and `SequenceAlert` as specified in RESEARCH.md
    2. `ToolCallMonitor.__init__(self, log_dir: Path | None = None)`:
       - Default log_dir = `~/.cloneguard/`
       - `log_dir.mkdir(parents=True, exist_ok=True)`
       - Open `monitor.log` in append mode with line buffering (`buffering=1`)
       - Initialize `_sessions: OrderedDict[str, deque[ToolEvent]]`
       - Initialize `_lock = threading.Lock()` (defensive thread safety)
    3. `record_event(self, data: dict[str, Any]) -> None`:
       - Extract fields: session_id, tool_use_id, tool_name, tool_input, hook_event_name (with hook_type fallback)
       - Create ToolEvent, append to session deque
       - Enforce _MAX_SESSIONS=200 via OrderedDict.popitem(last=False) eviction
       - Run all registered rules
       - Log any alerts via _log_alert
       - Entire method wrapped in try/except (never raises)
    4. Sequence rules as decorated functions (RESEARCH.md Pattern 3):
       - `_file_read_then_network` (SEQ-001): sensitive file Read then WebFetch to external URL within 10 events
       - `_file_read_then_curl` (SEQ-002): sensitive file Read then Bash curl/wget to external URL within 10 events
       - `_mcp_frequency_spike` (SEQ-003): same mcp__* tool >5 times in last 10 events
       - `_write_then_build` (SEQ-004): Write to sensitive target (.github/, package.json, Makefile, setup.py, pyproject.toml) then Bash build command within 10 events
    5. Helper functions:
       - `_is_sensitive_file(path)` — matches .env, secret, credential, password, token, key, .ssh/, id_rsa, id_ed25519
       - `_extract_external_url(tool_name, tool_input)` — uses urllib.parse.urlparse, returns None for localhost/127.0.0.1/::1/0.0.0.0
       - `_is_build_sensitive_target(path)` — matches build config files
       - `_is_build_command(command)` — matches npm/pip/make/cargo/go build/docker build patterns
    6. `_log_alert(self, alert)` — write JSONL entry with ts (ISO 8601 UTC), rule_id, description, session_id, trigger summary, context_window summary. Use `_summarize_input(event)` to avoid logging full tool_input.
    7. Module-level singleton: `_monitor: ToolCallMonitor | None = None` + `get_monitor(log_dir=None) -> ToolCallMonitor`
    8. `close(self)` method to flush and close log file handle (for test cleanup)

    **Anti-patterns to avoid (from RESEARCH.md):**
    - NEVER print() or write to sys.stdout from monitor code
    - NEVER open/close log file per event — open once in __init__
    - NEVER store tool_response/tool_output in ring buffer (can be large)
    - NEVER raise from record_event

    **Run tests (expect GREEN):** `uv run pytest tests/test_monitor.py -x -q`
