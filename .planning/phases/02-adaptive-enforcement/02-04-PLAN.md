<objective>
Implement package hallucination detection that cross-references npm/PyPI registries at install time.

Purpose: AI agents frequently hallucinate package names during pip install or npm install commands. A hallucinated package could be claimed by an attacker (slopsquatting). This detection signal catches non-existent packages before they are installed, feeding into the standard three-signal detection pipeline as an additional signal.

Output: PackageRegistryClient module with existence checks against npm/PyPI, package name extraction from install commands, and integration into DetectionEngine.scan_pre_tool_use().
</objective>

    1. Package name extraction from install commands:
    ```python
    """Package hallucination detection via registry API checks (D-15, D-16, D-17).

    Extracts package names from install commands (npm install, pip install) and
    cross-references against registry APIs (registry.npmjs.org, pypi.org) to detect
    hallucinated package names. Returns SignalResult objects that feed into the
    standard detection pipeline.

    Network failures always degrade gracefully -- skip check, log warning,
    never block the agent (D-17).
    """

    from __future__ import annotations

    import logging
    import re
    import urllib.error
    import urllib.request
    from typing import Any

    from cloneguard.detection.types import SignalResult

    logger = logging.getLogger(__name__)

    _REGISTRY_URLS = {
        "npm": "https://registry.npmjs.org/{package}",
        "pypi": "https://pypi.org/pypi/{package}/json",
    }

    _TIMEOUT = 3  # seconds (Pitfall 6: never block agent on slow network)
    ```

    2. extract_packages function:
    Parse install commands and extract package names. Handle common patterns:
    - npm install [flags] pkg1 pkg2 ... -> extract pkg names, skip flags (anything starting with -)
    - pip install [flags] pkg1 pkg2 ... -> extract pkg names, skip flags, skip -r/--requirement, skip . (local), skip git+ (VCS), strip version specifiers (==, >=, ~=, etc.)
    - pip3 install -> same as pip install
    - npm ci -> skip entirely (installs from lockfile, no individual packages)
    - yarn add pkg -> extract pkg names (yarn add is the install equivalent)

    Use regex to split the command after the install keyword and parse tokens:
    - _NPM_INSTALL_RE = re.compile(r"\bnpm\s+install\s+(.+?)(?:\s*[;&|]|$)")
    - _PIP_INSTALL_RE = re.compile(r"\b(?:pip3?)\s+install\s+(.+?)(?:\s*[;&|]|$)")
    - _YARN_ADD_RE = re.compile(r"\byarn\s+add\s+(.+?)(?:\s*[;&|]|$)")

    For pip packages with version specifiers (requests==2.31.0, flask>=2.0), strip the version part using split on ==, >=, <=, ~=, !=, >, <.

    Skip tokens that look like flags (-D, --save-dev, -r, --requirement), file paths (., ./, ../, /path, ./path), or VCS URLs (git+, svn+, hg+, bzr+).

    3. check_package function:
    ```python
    def check_package(self, package: str, registry: str) -> bool | None:
        """Check if package exists in registry. Returns True/False/None (error)."""
    ```
    - Build URL from _REGISTRY_URLS template
    - Use urllib.request.urlopen with timeout=_TIMEOUT
    - Use GET method (not HEAD -- npm HEAD not always reliable per research A3)
    - Accept: application/json header
    - 200 -> True (exists)
    - 404 -> False (hallucinated)
    - Any other error -> None (network issue, skip check)

    4. Session cache:
    ```python
    class PackageRegistryClient:
        def __init__(self) -> None:
            self._cache: dict[tuple[str, str], bool | None] = {}
    ```
    Cache keyed by (package_name, registry). Populated after each check_package call. Checked before making network request.

    5. check_packages_for_hallucination:
    ```python
    def check_packages_for_hallucination(
        self, command: str,
    ) -> list[SignalResult]:
        """Extract packages from command and check registries. Returns signals for hallucinated packages."""
    ```
    - Call extract_packages to get list of (name, registry) pairs
    - For each, call check_package (uses cache)
    - For each False result, create SignalResult:
      signal_type="package_hallucination", verdict="detected", confidence=0.95,
      details={"package": name, "registry": registry, "reason": "Package not found in {registry} registry"}
    - For each None result, log warning and skip (D-17: never block on network failure)
    - Return list of SignalResult (may be empty)

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Agent command to registry client | Package names extracted from untrusted tool_input commands |
| Registry API responses to verdict | 200/404 HTTP responses determine package existence |
| Network to CloneGuard process | Registry API calls cross network boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-17 | Spoofing | Registry API DNS spoofing | accept | Low risk for existence checks (attacker gains ability to make hallucinated packages appear real, which is already possible by registering the name). Future: add checksum verification for installed packages. |
| T-02-18 | Denial of Service | Registry API timeout blocks agent | mitigate | Hard 3-second timeout on all urllib.request calls (_TIMEOUT = 3). Network failures return None (skip check). Package hallucination is an additional signal, never a gate (D-17). |
| T-02-19 | Tampering | Crafted command string bypasses extraction | accept | Package name extraction uses regex on the command string. Adversarial command crafting (e.g., aliased commands, indirect invocation via scripts) may bypass extraction. This is detection-only -- missed checks fall through to existing pattern detection. False negatives are acceptable; false positives are not. |
| T-02-20 | Information Disclosure | Package names sent to public registries | accept | Package names are sent to public registries (npmjs.org, pypi.org) which are themselves public. No private information leaked. Internal package names may be disclosed to registry operators but this is inherent to the install command itself. |
</threat_model>
