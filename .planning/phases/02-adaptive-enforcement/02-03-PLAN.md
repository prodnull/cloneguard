<objective>
Implement OS-level sandbox adapters for Linux (Landlock LSM) and macOS (Seatbelt).

Purpose: These adapters provide real OS-level enforcement. When a detection result is SUSPICIOUS and enforcement is active (not dry-run), the sandbox adapter restricts the tool call subprocess to specific filesystem paths and network destinations. The critical constraint is that restrictions ONLY apply to the subprocess (via fork+restrict+exec pattern), never to the CloneGuard process itself.

Output: LandlockAdapter and SeatbeltAdapter modules with ctypes-based OS integration, both satisfying the SandboxAdapter Protocol.
</objective>

  <action>
    Create src/cloneguard/enforcement/landlock.py implementing the Landlock adapter.

    Architecture: The adapter does NOT call restrict_filesystem/restrict_network to apply restrictions immediately. It STORES the desired restrictions, then provides a get_preexec_fn() method that returns a callable applying restrictions in the child process between fork and exec. This is critical -- Landlock restrictions are irreversible and must only apply to the subprocess.

    Key constants (x86_64 and aarch64 use same syscall numbers):
    - SYS_LANDLOCK_CREATE_RULESET = 444
    - SYS_LANDLOCK_ADD_RULE = 445
    - SYS_LANDLOCK_RESTRICT_SELF = 446
    - PR_SET_NO_NEW_PRIVS = 38
    - LANDLOCK_RULE_PATH_BENEATH = 0x01
    - LANDLOCK_CREATE_RULESET_VERSION = 1 (flag for version query)
    - Filesystem access flags: READ_FILE=0x04, WRITE_FILE=0x08, READ_DIR=0x10, EXECUTE=0x01, MAKE_REG=0x40, MAKE_DIR=0x80

    Minimum always-allowed paths (Pitfall 2 from research):
    - Always writable: /tmp
    - Always readable: /tmp, /proc, /dev/null, /dev/urandom, /dev/zero, /usr/lib, /usr/local/lib, /lib, /lib64, /etc

    The LandlockAdapter class must implement:
    - __init__: detect ABI version by calling landlock_create_ruleset(NULL, 0, LANDLOCK_CREATE_RULESET_VERSION)
    - name property: return "landlock"
    - restrict_filesystem(writable, readable): store paths plus always-allowed paths
    - restrict_network(allow): store network rules if ABI >= 4, log and skip otherwise
    - get_preexec_fn() -> Callable or None: return closure that:
      1. prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0)
      2. landlock_create_ruleset with handled_access_fs bitmask
      3. landlock_add_rule for each readable path (READ_FILE | READ_DIR)
      4. landlock_add_rule for each writable path (READ_FILE | WRITE_FILE | READ_DIR | EXECUTE | MAKE_REG | MAKE_DIR)
      5. landlock_restrict_self(fd, 0)
      6. Close all opened fds
    - Deferred Protocol methods (snapshot, rollback, restrict_syscalls, get_audit_log): no-op implementations

    ctypes struct definitions needed:
    - LandlockRulesetAttr: handled_access_fs (uint64)
    - LandlockPathBeneathAttr: allowed_access (uint64), parent_fd (int32)

    If any syscall in preexec_fn fails (returns -1 with errno), the function returns silently (graceful degradation -- better to run unconfined than to crash the tool).

    Tests: All tests mock ctypes.CDLL and libc.syscall. No real Landlock calls in unit tests (would require Linux). Tests verify correct syscall numbers passed, correct struct layouts, prctl called before Landlock, graceful degradation when ENOSYS returned, always-allowed paths included, and ABI version detection.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CloneGuard process to child process | Sandbox restrictions applied at fork boundary via preexec_fn |
| Policy constraints to OS sandbox | User-supplied paths from policy.yaml become Landlock rules or SBPL subpaths |
| ctypes to kernel/libSystem | Raw syscalls/dylib calls at the OS boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-11 | Elevation of Privilege | CloneGuard restricts itself | mitigate | Landlock/Seatbelt only applied via preexec_fn in child process. Parent process never calls landlock_restrict_self or sandbox_init. Verified by test that parent retains full filesystem access after child restriction. |
| T-02-12 | Elevation of Privilege | Symlink escape from sandbox | mitigate | Landlock resolves symlinks natively (kernel built-in). Seatbelt: paths canonicalized with Path.resolve() before embedding in SBPL profile. |
| T-02-13 | Denial of Service | Sandbox breaks tool usage | mitigate | Always-allowed minimum paths (/tmp, /proc, system libs). Dry-run default (D-13). Graceful degradation: if sandbox application fails, child continues unrestricted (logged). |
| T-02-14 | Denial of Service | preexec_fn deadlock | accept | Low risk: CloneGuard hook handlers are single-threaded. preexec_fn uses only ctypes syscalls (no Python logging/string formatting). If deadlocks surface in production, migrate to compiled helper binary (documented in research). |
| T-02-15 | Tampering | SBPL injection via path strings | mitigate | All paths escaped: backslashes doubled, double-quotes escaped before embedding in SBPL. No eval or dynamic code generation in profile strings. |
| T-02-16 | Information Disclosure | Landlock ABI version leaks kernel info | accept | ABI version is minor info disclosure (kernel 5.13 vs 6.7). Logged at DEBUG level only. No security impact -- attacker already has uname. |
</threat_model>
